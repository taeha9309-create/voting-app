# 01: 기반 준비 — 테스트 환경과 스키마

**What to build:** 이후 모든 티켓이 기대는 바탕을 놓는다. 투표 모듈이 SQL 연결 하나를 주입받아 동작하고, 테스트에서는 PGlite, 배포에서는 Neon에 같은 스키마 SQL을 적용할 수 있는 상태를 만든다. 사용자에게 보이는 기능은 아직 없다. 자세한 결정은 `.scratch/club-voting/spec.md`의 "스키마", "전체 구조", "Testing Decisions"를 따른다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Vitest와 PGlite가 개발 의존성으로 추가되고, 테스트 실행 스크립트가 있다
- [ ] 투표, 선택지, 표 테이블을 만드는 스키마 SQL이 한곳에 있다. 스펙대로 무작위 UUID 식별값, 시간대 포함 마감 시각, (투표, 선택지 이름) 유일, (투표, 동아리원 식별값) 유일, 연쇄 삭제를 갖춘다
- [ ] 투표 모듈이 SQL 연결 하나를 주입받는 형태로 존재한다(동작은 아직 없어도 된다)
- [ ] 배포용 Neon 연결(`DATABASE_URL`)을 만들어 투표 모듈에 넘기는 곳이 한곳에 있다
- [ ] 테스트마다 새 PGlite 인스턴스에 스키마 SQL을 적용하는 테스트 도우미가 있고, 이를 쓰는 테스트 하나가 통과한다
- [ ] `.env.local` 예시 파일에 `DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET` 이름이 적혀 있다
- [ ] README에 스키마 SQL을 Neon에 적용하는 방법이 적혀 있다
- [ ] 구현 전에 `node_modules/next/dist/docs/`의 관련 가이드를 읽었다
